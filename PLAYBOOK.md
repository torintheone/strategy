# Порядок работы: какой модели что писать

Пошаговая инструкция для владельца проекта. Здесь — готовые сообщения для каждой оставшейся части игры, модель для каждой сессии и что делать между сессиями. Список частей — в [ROADMAP.md](ROADMAP.md).

## 1. Три модели и когда какая

| Модель | Как выбрать | Для чего |
| --- | --- | --- |
| **Opus 5.5** | `/model claude-opus-5-5` | Основная работа: новая часть игры, экраны, звук, исправление обычных ошибок |
| **Sonnet 5.5** | `/model claude-sonnet-5-5` | Контент по готовому образцу: события, законы, список портретов, тексты |
| **Fable 5.2** | `/model claude-fable-5-2` | Только трудное: баланс всей модели и ошибки, которые Opus не исправил с двух попыток |

Fable примерно вдвое дороже Opus и вчетверо дороже Sonnet. Если сомневаетесь — берите Opus.

Модель выбирается при создании сессии или командой `/model …` первым сообщением, до задания.

## 2. Один раз перед началом: перенести работу в основную ветку

Сейчас вся игра лежит в рабочей ветке `ccr-61ca050b-81z4lx`, а основная ветка `main` пустая. Новая сессия начинает с `main` и не увидит ни игру, ни памятку. Это нужно исправить один раз.

1. В этой сессии напишите: **«Создай pull request из рабочей ветки в main»**.
2. Откройте ссылку на pull request, которую пришлёт Claude, и нажмите зелёную кнопку **Merge pull request**, затем **Confirm merge**.
3. Дальше так же в конце каждой части: в сообщениях ниже это уже записано последней строкой.

## 3. Цикл одной части

Каждая часть — одна новая сессия. Порядок всегда один.

1. **Создать новую сессию** и выбрать модель из таблицы части.
2. **Отправить сообщение части** из раздела 4 — целиком, как написано. Если хотите что-то иначе, допишите в это же сообщение строку «Изменения: …».
3. **Ждать, ничего не писать.** Claude сам сообщает о ходе работы. «Продолжи» нужно писать, только если сессия остановилась с ошибкой или кончился лимит.
4. **Дождаться итога**: «что появилось» и «что проверить в игре».
5. **Нажать Merge** в pull request по ссылке из итога.
6. **Скачать сборку**: GitHub → вкладка **Actions** → верхний зелёный запуск «Сборка» → внизу страницы файл **Politeconomy-windows**. Распаковать целиком, запустить `Politeconomy.exe`.
7. **Проверить по шагам** из итога.
8. **Замечания — одним сообщением** в ту же сессию (шаблон в разделе 5). Если замечаний нет, сессию закрыть.
9. Следующая часть — снова с шага 1.

## 5. Шаблоны сообщений между частями

**Замечания после проверки** — в ту же сессию, одним сообщением:

```
Замечания по части X.Y:
1. <что не так и где: экран, кнопка, что ожидали увидеть>
2. …
Исправь всё одним заходом. Большие документы заново не читай.
В конце обнови pull request.
```

**Кончился лимит или сессия остановилась посреди части** — в ту же сессию, один раз:

```
Продолжи с того места, где остановился.
```

**Сессия потерялась** — новая сессия на той же модели:

```
Часть X.Y начата, но не закончена. Найди рабочую ветку прошлой сессии, посмотри её последние коммиты и доделай часть по ROADMAP.md.
В конце создай pull request в main.
```

**Ошибка в игре, найденная позже** — новая сессия на Opus:

```
Ошибка в игре: <что делали по шагам, что произошло, что должно было произойти>. Страна: <какая>. Дата в игре: <какая>.
Найди причину, исправь, добавь тест, чтобы ошибка не вернулась.
В конце создай pull request в main.
```

**Opus не исправил ошибку с двух попыток** — новая сессия на Fable:

```
Ошибка в игре, которую не удалось исправить: <описание>. Что уже пробовали: <коротко из прошлой сессии>.
Найди настоящую причину. Сначала объясни её в двух предложениях, потом исправляй.
В конце создай pull request в main.
```

**Хочу изменить то, что уже сделано** — новая сессия на Opus:

```
Изменение в готовой части: <что сейчас> → <как хочу>. Причина: <зачем>.
Обнови документы и запиши решение в DECISIONS.md.
В конце создай pull request в main.
```

## 6. Что не делать

- **Не просить «прочитай SPEC.md, MODEL.md и CHANGELOG.md».** Памятка `CLAUDE.md` загружается сама и говорит, что искать.
- **Не продолжать новую часть в старой сессии.** Каждое действие заново оплачивает всю историю беседы.
- **Не писать замечания по одному.** Каждое сообщение — отдельный ход с полной историей.
- **Не брать Fable для частей по образцу.** Результат тот же, расход вдвое больше.
- **Не давать Sonnet части с новой логикой игры.** Он для контента по готовому образцу.
- **Не пропускать Merge.** Без него следующая сессия не увидит сделанное.
